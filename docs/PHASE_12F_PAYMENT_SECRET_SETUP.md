# Elégance — Phase 12F: Payment Secret Setup & Key Management Guide

**Document:** Environment Secret Setup & Secure Credential Handling  
**Phase:** 12F Architecture / Phase 15 Activation  
**Security Classification:** Confidential / Operational Security  

---

## 1. Secret Inventory & Naming Conventions

The Elégance platform standardizes all commercial billing configuration around explicit environment variables:

| Environment Variable | Target Provider | Description | Sensitivity |
|:---|:---:|:---|:---:|
| `BILLING_PROVIDER` | Core | Active provider identifier (`disabled`, `fake`, `razorpay`, `stripe`) | Low |
| `BILLING_GRACE_PERIOD_DAYS` | Core | Grace period duration in days when payment fails (default: 7) | Low |
| `BILLING_CURRENCY` | Core | ISO 4217 billing currency (default: `INR`) | Low |
| `RAZORPAY_KEY_ID` | Razorpay | Public Key ID generated in Razorpay Dashboard | Medium |
| `RAZORPAY_KEY_SECRET` | Razorpay | Private Secret Key for API authorization | **Critical** |
| `RAZORPAY_WEBHOOK_SECRET` | Razorpay | Shared HMAC secret for verifying `X-Razorpay-Signature` | **Critical** |
| `STRIPE_API_KEY` | Stripe | Restricted or Secret Key (`sk_live_...` or `rk_live_...`) | **Critical** |
| `STRIPE_WEBHOOK_SECRET` | Stripe | Webhook endpoint secret for verifying `Stripe-Signature` (`whsec_...`) | **Critical** |
| `STRIPE_TIMESTAMP_TOLERANCE_SECONDS` | Stripe | Replay tolerance window in seconds (default: 300) | Low |

## 2. Environment Matrix

```
+------------------------------------------------------------------------------------+
|                         SECRET ISOLATION ACROSS ENVIRONMENTS                       |
+------------------------------------------------------------------------------------+
|                                                                                    |
|  [Local Development]          [Staging / CI/CD]            [Live Production]       |
|  -------------------          -----------------            -----------------       |
|  BILLING_PROVIDER=disabled    BILLING_PROVIDER=disabled    BILLING_PROVIDER=       |
|  or fake                      (or test-mode keys)          disabled (Phase 15      |
|  No live keys required        Dedicated sandbox keys       Pending) / live keys    |
|                               Isolated test webhook        Hardware/Vault Secrets  |
|                                                            Zero Git Commit         |
+------------------------------------------------------------------------------------+
```

### 2.1 Local Development
- Default: `BILLING_PROVIDER=disabled` or `fake`.
- Zero external network calls.
- Never place live provider API keys into local `.env` files.

### 2.2 Staging / CI/CD
- Use dedicated **Test Mode** keys (`rzp_test_...` or `sk_test_...`).
- Managed through CI/CD environment secrets (GitHub Secrets / Render Environment Secrets).
- Automated tests run against mock/contract providers or local databases without hitting real provider APIs.

### 2.3 Live Production (Phase 15 Activation)
- Use dedicated **Live Mode** keys generated by authorized administrators.
- Managed exclusively via production Secret Store / Vault (e.g., AWS Secrets Manager, Render Secret Groups, Cloudflare Encrypted Secrets).
- Strictly forbidden from being logged in console logs, exception traces, or error payloads.

## 3. Secret Rotation Procedures

### 3.1 Razorpay Key Rotation
1. Log in to the Razorpay Dashboard.
2. In **Settings -> API Keys**, generate a **New Key**. Razorpay provides a 24-hour grace window during which both the old and new keys remain valid.
3. Update `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` in the production secret store.
4. Trigger a rolling restart of `apps/api`.
5. Verify successful checkout initiation in staging/production.
6. Revoke the old key in the Razorpay Dashboard.

### 3.2 Stripe Key & Webhook Secret Rotation
1. For API Keys: In **Stripe Dashboard -> Developers -> API Keys**, generate a new restricted key with limited permissions (`checkout.sessions:write`, `subscriptions:write`, `invoices:read`).
2. Update `STRIPE_API_KEY` in production secrets.
3. For Webhook Secrets: Stripe allows adding multiple endpoints or rolling secrets with a grace period. Generate a new signing secret, update `STRIPE_WEBHOOK_SECRET`, and revoke the previous secret after deployment.

## 4. Leak Prevention & Audit Controls

1. **Pre-commit Hooks:** Git hooks prevent committing files containing `sk_live_`, `rzp_live_`, or `whsec_`.
2. **Exception Scrubbing:** All billing exception handlers in `apps/api` sanitize internal stack traces. Webhook signature calculation routines never print secrets or calculated hashes to stdout or logs.
3. **Audit Logging:** Administrative updates to subscription tiers or payment states are logged to `audit_events` with actor ID, timestamp, and remote IP address.
