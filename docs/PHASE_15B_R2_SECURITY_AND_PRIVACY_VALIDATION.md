# Phase 15B — Cloudflare R2 Security & Privacy Validation Specification

## 1. Security Architecture Principles

In the **Elégance — Interior Designer Platform**, media files represent proprietary residential design plans, private client home interiors, and commercial blueprints. The storage security architecture enforces five core security guarantees:

1. **Strict Multi-Tenant Isolation**: Studio media keys are strictly partitioned by `studio_id` at both the object storage layer and database layer.
2. **Short-Lived Ephemeral Upload Credentials**: Direct browser uploads use cryptographically signed S3 presigned PUT URLs with a strict 30-minute expiration window.
3. **No Public Access to Originals**: High-resolution originals and CAD/render source files are stored in the private bucket and are never publicly accessible without authentication.
4. **Automated Metadata & Privacy Sanitization**: EXIF metadata, GPS latitude/longitude, and camera identifiers are stripped before derivatives are exposed.
5. **Fail-Closed Malware Containment**: No object is promoted to canonical storage without passing a ClamAV malware scan.

---

## 2. Multi-Tenant Partitioning & Path Traversal Defense

### Storage Key Path Hierarchy
Every object path is constructed strictly on the backend using validated database UUIDs:
```
Private Bucket:
pending/{studioId}/{uploadIntentId}/source.{ext}
studio/{studioId}/projects/{projectId}/original/{mediaId}.{ext}

Public Bucket:
public/studio/{studioId}/projects/{projectId}/derivatives/{mediaId}_{size}.webp
```

### Path Traversal Defense:
- Client-provided filenames (e.g. `../../etc/passwd` or `project/photo.jpg`) are never used in the storage key.
- The platform generates canonical object keys using UUIDv7 identifiers.
- The original filename is stored safely as a sanitized string in the PostgreSQL database column `media.original_filename` for display purposes only.

## 3. Presigned PUT Security Envelope

The presigned upload URL generated by `S3StorageService.generateUploadUrl` adheres to the following constraints:

```java
PutObjectPresignRequest presignRequest = PutObjectPresignRequest.builder()
    .signatureDuration(Duration.ofMinutes(30))
    .putObjectRequest(PutObjectRequest.builder()
        .bucket(properties.getS3().getPrivateBucket())
        .key(quarantineKey)
        .contentType(contentType)
        .build())
    .build();
```

| Security Constraint | Implementation | Rationale |
|---|---|---|
| **Expiry Window** | Fixed at 30 minutes (`Duration.ofMinutes(30)`) | Prevents leaked or intercepted URLs from being reused indefinitely. |
| **Fixed Target Key** | Bound strictly to `pending/{studioId}/{intentId}/...` | Client cannot upload to arbitrary prefixes or overwrite other assets. |
| **Content-Type Binding** | Bound to the MIME type declared during intent creation | Client cannot upload an executable binary under an image presigned URL. |
| **No Wildcards** | Exact key path only | Browser cannot perform multi-file or directory uploads with one token. |

## 4. API Token Least-Privilege Scoping in Cloudflare

When provisioning the Cloudflare R2 API Token in the Cloudflare Dashboard:
- **Permissions Selected**: `Object Read & Write`
- **Permissions Excluded**:
  - `Admin Read & Write` (Excluded — prevents token from creating/deleting buckets)
  - `Account Read & Write` (Excluded — prevents token from modifying Cloudflare account settings)
- **Bucket Restriction**: Token must be scoped specifically to:
  - `interior-platform-media-private`
  - `interior-platform-media-public`
- **Zero Plain-Text Credential Storage**: R2 Access Key ID and Secret Access Key must reside strictly in `.env.local` or environment variables; never committed to Git.

## 5. EXIF & Client Privacy Scrubbing

Interior design photography taken on modern mobile devices or DSLR cameras embeds detailed metadata:
- **GPS Coordinates**: Exact location of high-net-worth client residences.
- **Camera Device Data**: Serial numbers, firmware versions, lens profiles.
- **Timestamp Information**: Exact dates and times when photos were taken inside client residences.

### Sanitization Implementation:
The platform's processing pipeline decodes uploaded image byte arrays, strips all EXIF IFD0, Exif SubIFD, and GPS IFD metadata tags, and re-encodes the image into modern WebP format.

**Retained Metadata**:
- ICC Color Profile (to ensure wall paint colors, fabrics, and lighting render true-to-life on display monitors).

## 6. Database Row-Level Security Integration

Media metadata in PostgreSQL is protected by Row-Level Security (`FORCE ROW LEVEL SECURITY`):
```sql
ALTER TABLE media ENABLE ROW LEVEL SECURITY;
ALTER TABLE media FORCE ROW LEVEL SECURITY;

CREATE POLICY media_studio_isolation_policy ON media
    FOR ALL
    USING (studio_id = NULLIF(current_setting('app.current_studio_id', true), '')::uuid);
```

Even if a malicious user guesses the UUID of another studio's media asset, the database engine returns zero rows (`404 NOT FOUND`), preventing metadata leakage, project association theft, or unauthorized deletion requests.
