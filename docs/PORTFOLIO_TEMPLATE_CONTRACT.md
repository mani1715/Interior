# Portfolio Template Contract & Engine Specification
## Phase 10.1 Canonical Alignment

This specification defines the formal contract between the shared **Portfolio Engine** (built in Phase 10 and aligned in Phase 10.1) and the **Visual Portfolio Themes** to be created by Astra in subsequent phases:
- **Phase 11**: Basic Clean Editorial (`BASIC`)
- **Phase 12**: Modern Minimalist (`MODERN`)
- **Phase 13**: Luxury Atelier (`LUXURY`)
- **Phase 14**: Architectural Monograph (`ARCHITECTURAL`)
- **Phase 15**: Warm & Natural Organic (`WARM_NATURAL`)
- **Phase 16**: Dark Cinematic Moodboard (`DARK_CINEMATIC`)
- **Phase 17**: Antigravity Integration, Theme Engine Consistency, Responsive QA & Regression

---

## 1. Fundamental Invariant: Content != Template

The platform strictly decouples **persisted portfolio domain content and structure** from **visual presentation templates**:

1. An interior designer or studio can switch between any of the six aesthetic themes at any time from the workspace builder.
2. Switching themes updates only `portfolios.template_key`.
3. **No section data, text, configuration, or display order is destroyed, mutated, or lost during a template switch.**
4. When a designer switches from `BASIC` to `LUXURY` and then back to `BASIC`, the entire content tree remains intact and identical.
5. Content is persisted in normalized relational tables (`portfolios`, `portfolio_sections`) and delivered to the template as a clean, immutable props object.

## 3. Navigation Settings Contract & Normalization

`navigationSettings` is a non-null, strongly-typed presentation contract generated by `normalizePortfolioProps()` (located in `apps/web/src/lib/portfolio/normalize-props.ts`).

Templates can safely consume `props.navigationSettings` without null-checks:
- `sticky`: `boolean` — whether the top studio navigation bar stays sticky upon scroll.
- `navItems`: `NavItem[]` — ordered list of anchors (`#about`, `#services`, `#projects`, etc.) derived from currently visible sections.
- `showPrimaryCta`: `boolean` — whether to render the header consultation button.
- `primaryCtaLabel`: `string` — defaults to `"Request Consultation"`.
- `primaryCtaAnchor`: `string` — anchor link target, defaults to `"#contact"`.

## 4. Canonical Font Pairings (6 Exact Enums)

The database schema (`V006__portfolio_engine.sql`) and backend enum `FontPairing.java` enforce exactly 6 canonical font pairings:

1. `SYSTEM_SANS`: Modern system sans-serif (`font-sans font-medium`).
2. `CLASSIC_SERIF`: Refined transitional serif (`font-serif`).
3. `MODERN_CLEAN`: Crisp high-contrast geometric sans (`font-sans tracking-tight`).
4. `EDITORIAL`: Literary high-fashion editorial serif (`font-serif tracking-wide`).
5. `WARM_EDITORIAL`: Organic italic serif (`font-serif italic`).
6. `BOLD_CINEMATIC`: Heavy architectural sans (`font-sans font-black tracking-tight`).

## 5. Canonical Section Types (18 Exact Enums & v1 Schemas)

The database schema and backend validator `PortfolioSectionValidator.java` enforce exactly 18 canonical section types with structured `content` payloads:

| SectionType | Purpose | Key Content Fields |
|---|---|---|
| `HERO` | Visual banner & primary value statement | `headlineOverride`, `subheadlineOverride`, `badgeText`, `ctaText`, `ctaLink` |
| `ABOUT` | Studio narrative & design leadership | `narrativeOverride`, `philosophyOverride`, `yearsOverride`, `signatureUrl` |
| `SERVICES` | Practice trade offerings | `sectionHeadline`, `sectionSubheadline`, `customOfferings: []` |
| `FEATURED_PROJECTS` | Selected highlight case studies | `sectionHeadline`, `projectIds: []`, `layoutStyle` |
| `PROJECT_GRID` | Comprehensive project gallery | `sectionHeadline`, `columns`, `filterEnabled` |
| `BEFORE_AFTER` | Architectural transformation comparisons | `sectionHeadline`, `pairs: [{ beforeImageUrl, afterImageUrl, title, caption }]` |
| `BEFORE_AI_REALITY` | AI concept vs reality comparisons | `sectionHeadline`, `pairs: [{ conceptImageUrl, realityImageUrl, title }]` |
| `DESIGN_PROCESS` | Step-by-step studio methodology | `sectionHeadline`, `steps: [{ stepNumber, title, description }]` |
| `TESTIMONIALS` | Client reviews & endorsements | `sectionHeadline`, `testimonials: [{ quote, clientName, projectLocation, rating }]` |
| `TEAM` | Lead architects & design team | `sectionHeadline`, `members: [{ name, role, photoUrl, bio }]` |
| `AWARDS` | Accolades, honors & distinctions | `sectionHeadline`, `items: [{ title, issuer, year }]` |
| `PRESS` | Media features & publications | `sectionHeadline`, `articles: [{ publication, title, url, publishDate }]` |
| `SERVICE_AREAS` | Geographic regions & localities | `sectionHeadline`, `introText` |
| `FAQ` | Frequently asked questions | `sectionHeadline`, `questions: [{ question, answer }]` |
| `CONTACT` | Inquiries & studio channels | `contactIntro`, `formEnabled`, `buttonText` |
| `CTA` | Consultation banner | `headline`, `subheadline`, `buttonText`, `buttonLink` |
| `VIDEO` | Studio reel or video walkthrough | `videoUrl`, `title`, `caption` |
| `CUSTOM_NOTE` | Custom editorial statement | `title`, `body` |

### Section Rendering Invariants
- **Sort Order**: Templates must render sections strictly ordered by `displayOrder` ascending.
- **Empty States**:
  - *Projects*: Zero projects must render a graceful empty state (e.g. `"Projects In Curation"`). Never throw an error or leave an empty broken container.
  - *Testimonials*: Empty reviews must render cleanly or collapse gracefully.
- **Strict Privacy**:
  - `publicContacts` strictly contains contacts where `publicConsent == true`.
  - Templates must never attempt to access private phone numbers or unconsented email addresses.
- **Security**:
  - Templates must **NEVER** use `dangerouslySetInnerHTML` or evaluate unsanitized HTML/JS.

## 7. The Six Canonical Template Keys & Lifecycles

| Template Key | Visual Identity & Direction | Target Phase | Status | Version | Selectable |
|---|---|---|---|---|---|
| `BASIC` | Clean editorial typography, balanced whitespace, clear hierarchy | Phase 11 | `SCAFFOLD` | `1.0.0` | `false` |
| `MODERN` | Asymmetrical grid, high contrast, sans-serif dominance | Phase 12 | `SCAFFOLD` | `1.0.0` | `false` |
| `LUXURY` | Opulent serifs, warm bronze accents, spacious pacing | Phase 13 | `SCAFFOLD` | `1.0.0` | `false` |
| `ARCHITECTURAL` | Structured drafting grid, technical precision, geometric discipline | Phase 14 | `SCAFFOLD` | `1.0.0` | `false` |
| `WARM_NATURAL` | Earthy terracotta/sand tones, biophilic textures, organic warmth | Phase 15 | `SCAFFOLD` | `1.0.0` | `false` |
| `DARK_CINEMATIC` | Deep obsidian backdrop, dramatic lighting focal points | Phase 16 | `SCAFFOLD` | `1.0.0` | `false` |

### Graduating a Template: `SCAFFOLD` → `AVAILABLE`
All templates initially have `status: 'SCAFFOLD'` and `isSelectable: false`. When Astra finishes a template in its assigned phase:
1. Astra creates the template component in its respective directory.
2. In `apps/web/src/lib/portfolio/template-registry.tsx`, Astra imports the component and updates:
   ```typescript
   BASIC: {
     key: 'BASIC',
     name: 'Clean Editorial',
     tagline: 'Simple, typography-driven portfolio for emerging designers',
     description: '...',
     version: '1.0.0',
     status: 'AVAILABLE', // <-- Changed from 'SCAFFOLD'
     isSelectable: true,   // <-- Enabled
     supportedSections: CANONICAL_SECTION_TYPES,
     designer: 'Astra (Phase 11)',
     phase: 'Phase 11',
     component: BasicTemplate, // <-- Real template component
   }
   ```
3. `ReferenceTemplate.tsx` is **ENGINE TEST/REFERENCE ONLY**. It is **NOT** the final Basic design.

## 8. Ownership Boundaries: Astra vs Engine

### What Astra May Edit (Phases 11–16)
- Files inside `apps/web/src/components/portfolio/templates/<theme-name>/**`
- Adding visual components, styling modules, typography tokens, and decorative SVGs for the theme.
- Registering the finished theme in `apps/web/src/lib/portfolio/template-registry.tsx` (changing its status from `SCAFFOLD` to `AVAILABLE` and `isSelectable: true`).
- Writing theme-specific unit tests under `apps/web/src/components/__tests__/` (e.g., `BasicTemplate.test.tsx`).

### What Astra Must NEVER Edit (Engine-Owned)
- **Backend Java code** (`apps/api/**`)
- **Database migrations** (`V001` through `V006`)
- **Authentication, sessions, CSRF, and authorization**
- **Portfolio engine API client or endpoints** (`portfolio/api.ts`, `PortfolioController.java`)
- **Section schema validation** (`PortfolioSectionValidator.java`)
- **Optimistic concurrency & version snapshots**
- **The `PortfolioTemplateProps` contract** (`apps/web/src/lib/portfolio/template-contract.ts`)
- **Global workspace shell and navigation**
