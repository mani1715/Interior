# Phase 15B — Cloudflare R2 Storage Architecture & Live Validation Specification

## 1. Executive Summary

This document defines the production specification and integration boundary for **Cloudflare R2 Object Storage** within the **Elégance — Interior Designer Platform**.

Cloudflare R2 serves as the primary object storage for interior design portfolio assets, client project deliverables, before/after transformations, room specifications, and generated AI concept imagery. The platform connects to R2 using the standard AWS SDK for Java (v2) over an S3-compatible API.

> [!NOTE]
> Per platform architecture policy, Cloudflare R2 is treated strictly as an **S3-compatible API target**; it is never described as "100% S3 compatible". The platform relies exclusively on a bounded 6-operation primitive subset supported identically across S3-compatible providers.

---

## 2. Minimal 6-Operation Storage Contract

The Elégance platform runtime (`S3StorageService.java`) interacts with Cloudflare R2 strictly via the following 6 operations:

| # | Operation | AWS SDK Call | Purpose in Elégance | Bucket Target |
|---|---|---|---|---|
| **1** | **Presigned PUT** | `s3Presigner.presignPutObject(PutObjectPresignRequest)` | Generates time-bounded (30-minute) presigned URLs for direct browser uploads. No direct binary upload passes through backend servers during client intake. | Private Quarantine Bucket (`pending/`) |
| **2** | **PutObject** | `s3Client.putObject(PutObjectRequest, RequestBody)` | Stores processed derivatives, thumbnails, web-optimized WebP assets, and platform metadata. Sets `Cache-Control: public, max-age=31536000, immutable` for public derivatives. | Public Bucket (`public/`) or Private Bucket (`studio/`) |
| **3** | **GetObject** | `s3Client.getObjectAsBytes(GetObjectRequest)` | Fetches quarantine binaries for ClamAV streaming scanning, EXIF stripping, and WebP transcoding. | Private Quarantine Bucket (`pending/`) |
| **4** | **HeadObject** | `s3Client.headObject(HeadObjectRequest)` | Verifies object existence, byte size, and Content-Type integrity before confirming database records. | Private or Public Bucket |
| **5** | **CopyObject** | `s3Client.copyObject(CopyObjectRequest)` | Promotes verified, malware-clean objects from quarantine prefix (`pending/`) to canonical studio storage (`studio/`). | Private Bucket (atomic internal copy) |
| **6** | **DeleteObject** | `s3Client.deleteObject(DeleteObjectRequest)` | Prunes quarantine files post-promotion, deletes deleted media, and enforces GDPR/retention purges. | Private or Public Bucket |

### Excluded S3 APIs (Forbidden by Policy)
The platform **never** executes:
- `CreateBucket` / `DeleteBucket` (buckets are provisioned administratively via Cloudflare dashboard or Terraform).
- `ListObjects` / `ListObjectsV2` (all object locations and keys are indexed in PostgreSQL tables; bucket listings are forbidden for cost and security reasons).
- S3 Object ACLs (R2 does not support S3 ACLs; access control is managed via presigned URLs and Cloudflare access rules).
- Multipart uploads (single-part PUT is enforced for all images up to the 50 MB platform cap).

## 3. Dual-Bucket Architecture & Namespace Isolation

The platform establishes strict cryptographic and logical separation between private source media and public derivatives:

```
Cloudflare R2 Storage Topology
├── Private Bucket: interior-platform-media-private
│   ├── pending/{studioId}/{uploadIntentId}/original.{ext}   [Quarantine — 30-min TTL]
│   └── studio/{studioId}/projects/{projectId}/original/     [Canonical Private Originals]
│
└── Public Bucket: interior-platform-media-public
    └── public/studio/{studioId}/projects/{projectId}/derivatives/
        ├── hero_1920x1080.webp                              [Cache-Control: public, max-age=31536000]
        ├── thumbnail_400x300.webp
        └── spec_sheet_optimized.webp
```

### Access Boundaries:
1. **Private Bucket (`interior-platform-media-private`)**:
   - Direct public access disabled.
   - S3 credentials have read/write access.
   - Accessed by browsers only via short-lived (30-min) presigned PUT/GET URLs generated by the API.
2. **Public Bucket (`interior-platform-media-public`)**:
   - Contains only sanitized, EXIF-stripped, WebP/AVIF web derivatives approved for portfolio display.
   - Served via Cloudflare Custom Domain / CDN in Phase 16 (`https://media.elegance.interior/public/...`).

## 4. Environment Configuration & Variable Mapping

The following environment variables configure Cloudflare R2 integration:

| Environment Variable | Required | Production Value / Pattern | Description |
|---|---|---|---|
| `MEDIA_STORAGE_PROVIDER` | **Yes** | `S3_COMPATIBLE` | Enables S3-compatible cloud storage driver in Spring Boot |
| `S3_ENDPOINT` | **Yes** | `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` | Cloudflare R2 S3 API endpoint URL |
| `S3_REGION` | **Yes** | `auto` | Cloudflare R2 region (always `auto`) |
| `S3_ACCESS_KEY_ID` | **Yes** | `<R2_ACCESS_KEY_ID>` | Cloudflare R2 API Token Access Key ID |
| `S3_SECRET_ACCESS_KEY` | **Yes** | `<R2_SECRET_ACCESS_KEY>` | Cloudflare R2 API Token Secret Access Key |
| `S3_BUCKET_PRIVATE` | **Yes** | `interior-platform-media-private` | Private bucket for quarantine and high-res originals |
| `S3_BUCKET_PUBLIC` | **Yes** | `interior-platform-media-public` | Public bucket for portfolio web derivatives |
| `PUBLIC_MEDIA_BASE_URL` | No | `https://media.elegance.interior` | CDN base URL for public asset delivery (Phase 16) |

## 5. Security & Token Permission Policy

Cloudflare R2 API tokens must be created with minimal least-privilege permissions:
- **Permission**: `Object Read & Write` (Admin / Bucket Management permissions must **NOT** be granted).
- **Scope**: Applied specifically to the two designated buckets:
  1. `interior-platform-media-private`
  2. `interior-platform-media-public`
- **TTL / Expiry**: Set according to studio operational policy; rotated bi-annually.
- **Client IP Restriction**: If supported by the network tier, restrict token usage to the backend container egress IPs.

## 6. Live Verification Harness (`scripts/verify-r2-live-integration.ps1`)

The verification script provides two operation modes:
1. **Pre-Validation / Readiness Mode (Default)**:
   - Validates that all codebase contracts, ClamAV integration, PostgreSQL RLS security tests, and S3 drivers are compile-safe and pass 100% of contract tests.
2. **Live Cloud Execution Mode (`-RequireLive`)**:
   - Executes `R2LiveIntegrationTest.java` against the live Cloudflare R2 endpoint.
   - Creates an isolated test object under `integration-tests/<run-id>/live-contract-test.txt`.
   - Executes PutObject, HeadObject, GetObject, CopyObject, DeleteObject, and 404 confirmation.
   - Cleans up all test artifacts in `finally` block.
   - Zero test data leaked outside the ephemeral test prefix.
